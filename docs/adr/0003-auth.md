# ADR-0003 — Auth: argon2id + httpOnly cookies + double-submit CSRF

- **Status:** accepted
- **Context:** Spec requires argon2, httpOnly cookies or short-lived tokens+refresh, CSRF, security headers, rate limiting.
- **Decision:** argon2id (default OWASP params) via `pwdlib`/`argon2-cffi`. Sessions are JWT access (15 min) + opaque refresh (HTTP-only, 14 days). CSRF via double-submit cookie pattern: `tl_csrf` cookie set on login, `X-CSRF-Token` header required on unsafe verbs. Refresh rotation; reuse-detection invalidates the family.
- **Consequences:**
  - Stateless access tokens keep WebSockets simple (validate JWT on `connect`).
  - Cookie auth + CSRF is browser-native; no manual token plumbing in the React client.
  - Reuse detection requires the refresh store; we use Postgres with a hash of the refresh token, not the token itself.
- **Alternatives considered:**
  - Sessions in Redis — adds a runtime dependency and complicates WebSocket auth (extra round trip).
  - Pure Authorization header tokens + refresh in body — works, but breaks browser `fetch` ergonomics and CSRF becomes a manual concern.
